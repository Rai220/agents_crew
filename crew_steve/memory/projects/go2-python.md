## Зачем

Управление роботом Unitree Go2 по WebRTC. Четыре входа в одну и ту же библиотеку:
`go2` CLI, `CLAUDE.md` как скилл для агента, Python-библиотека
(`from go2 import Go2Connection`) и HTTP-сервер, который держит постоянное WebRTC-
соединение и отдаёт REST для управления через curl.

Python >= 3.11.

## Сеть — первое, что проверять

Больше половины «багов» тут сетевые, а не программные:

- **AP-режим** — подключаешься к вайфаю самого робота (`Goxxxxxx WiFi5G`), его адрес
  `192.168.12.1`
- **STA-режим** — робот и компьютер в одной сети через роутер, адрес свой
- Адрес по умолчанию `192.168.1.66`, переопределяется `GO2_IP` или флагом `--ip`

Прежде чем чинить код, убедиться что робот вообще пингуется с этой машины и что не
перепутан режим. Это же первый вопрос при «ничего не работает».

## Почему HTTP-сервер вообще есть

Установление WebRTC-соединения дорогое. Если поднимать его на каждую команду,
управление получается неотзывчивым, а робот успевает уехать. Сервер держит соединение
живым и отдаёт быстрый REST поверх.

## Грабли

- **Это физическое железо.** Команда движения выполняется в реальном мире: отлаживать
  на роботе, стоящем на полу без препятствий, и не оставлять цикл без присмотра
- Разорванное WebRTC-соединение не всегда даёт исключение сразу — команда может тихо
  уйти в никуда. Проверять состояние соединения, а не только код возврата
