# crew console

Локальный веб-чат со всей командой: вкладка на сотрудника, у каждого свой тред и своё
лицо. Нужен [uv](https://docs.astral.sh/uv/).

```sh
../run.sh          # → http://127.0.0.1:8766, браузер откроется сам
```

`run.sh` лежит в корне репозитория — это `uv run server.py` с проверкой порта до старта
и пробросом аргументов (`--host`, `--port`). Проверка нужна потому, что занятый порт
uvicorn не отбирает, см. «Грабли» ниже.

## Что умеет

- Enter — отправить, Shift+Enter — перенос строки.
- Видно, какие инструменты агент дёргает, сколько идёт запуск и насколько он был
  тяжёлый. Серия вызовов свёрнута до трёх строк: пока агент работает, в них бежит
  хвост списка, а кнопка разворачивает всё. Так десяток `Read` подряд не вытесняет
  с экрана сам ответ.
- Под полем ввода — тумблеры проектов сотрудника. Отмеченные подставляются в начало
  вопроса («речь идёт о проектах …, загляни в заметки по ним»), поэтому агент открывает
  нужную память сам, без напоминаний. Выбор свой у каждого сотрудника и переживает
  перезагрузку страницы.
- Когда сотрудник зовёт соседа, это отдельный блок с аватаром вызванного: видно
  вопрос и ответ. Ответ соседа свёрнут — он обычно длиннее всего остального разговора.
- Кнопка «Стоп» убивает всё дерево процессов, а не только верхний.
- **«⟳ Новый диалог»** — сбросить контекст. Рядом написано, сколько вопросов накопил
  текущий тред, чтобы было видно, когда пора. Жмётся в два шага: первый клик взводит
  кнопку, второй сбрасывает. Сброс настоящий: сотруднику заводится новая сессия
  (`--session-id` вместо `--resume`). Долговременная память в `memory/` при этом
  никуда не девается — забывается разговор, а не сотрудник.

Запуск живёт на сервере, а не в HTTP-запросе. Поэтому можно обновить вкладку посреди
пятиминутного ответа, закрыть крышку или открыть ту же страницу с телефона — лента
дособерётся с того места, где оборвалась.

## Агенты знают, кто пишет

Без этого агент не отличает человека от скрипта и от другого агента. Каждый запуск
получает преамбулу: собеседник — человек, канал — веб-чат, ответ придёт в браузер.
Уезжает она в `--append-system-prompt`, так что в ленте её не видно и с текстом вопроса
она не смешивается.

Самый неочевидный пункт преамбулы — **вывод инструментов человеку не показывают**, в
ленте только их названия. Без этой оговорки агент отвечает «смотри выше», а смотреть
некуда; с ней — пересказывает найденное словами.

Текст — `CLAUDE_PREAMBLE` в `server.py`. Имя собеседника — переменная окружения
`CREW_CALLER` (по умолчанию «создатель»).

## Аватары

Лежат в `avatars/<агент>.jpg`, 256×256. Отдаются только по ключам из реестра `AGENTS`,
поэтому произвольный путь через этот эндпоинт не вытащить.

Новому сотруднику: положить `avatars/<id>.jpg`. Без файла будет серый круг, ничего
не сломается — у Лоры в этом примере аватара нет намеренно, посмотреть можно на ней.

Аватары Стива и Альфреда сгенерированы по описанию роли. Если будешь делать свои —
проси архетип («пожилой английский дворецкий»), а не персонажа и не лицо конкретного
актёра: узнаваемо по роли и без чужой интеллектуальной собственности.

## Откуда берутся проекты

Из заметок в `memory/projects/*.md` дома сотрудника, на каждый запрос. Завёл заметку —
тумблер появился сам, ничего править не надо.

На кнопке — название из поля `name:` заметки, до тире: там сохранён регистр (`LoRA`,
`PyTorch`), которого в именах файлов нет. Если названия нет или оно длиннее 26
символов, показывается имя файла. Агенту уходит и то, и другое: по названию понятно, о
чём речь, по файлу — что открыть.

**У Альфреда на тумблерах не проекты, а системы** — его единица знания не проект, а
доступ: заметки лежат в `memory/access/`, и в вопрос подставляется «речь идёт о
системах …». Задаётся в реестре двумя ключами, `notes_dir` и `notes_word`; у остальных
их нет, и по умолчанию читается `memory/projects/`.

## Про цифру стоимости

`≈$0.04` под ответом — **не списание**. В событии `init` приходит `apiKeySource: none`,
то есть вход по подписке: `total_cost_usd` считается пересчётом токенов по тарифам API
и показывает, насколько тяжёлым был запрос. Деньги по нему не уходят, расходуется лимит
плана. При входе по API-ключу консоль это заметит и покажет ровный `$0.04` без «≈».

## Права

**У сотрудников полный доступ**: они правят файлы и запускают команды без подтверждений.
Это осознанный выбор — консоль это твой личный канал к ним, а не консультация агента с
агентом (то ограничение живёт в их `AGENTS.md` и здесь не действует).

Из-за этого сервер по умолчанию слушает только `127.0.0.1`. Открыть его наружу без
токена нельзя — стартовать откажется:

```sh
CREW_CONSOLE_TOKEN=$(openssl rand -hex 16) ../run.sh --host 0.0.0.0
```

Телефон подключается один раз по `/?t=<токен>`, дальше работает по куке.

## Как устроено

Один файл на сервере (`server.py`) и один на фронте (`index.html`), без сборки и npm.

У каждого агента append-only журнал событий в `data/<агент>.jsonl` — он же транскрипт
для UI, он же буфер для догона. Браузер читает его через SSE с нужного индекса
(`/api/events/<агент>?from=N`). Журнал переживает перезапуск сервера; оборванные им
запуски помечаются `stopped`, а не перезапускаются молча.

Сотрудник поднимается `claude` с рабочим каталогом в его доме, поэтому подхватываются
его `AGENTS.md` и `memory/`. Непрерывность треда — родная, через `--session-id`/`--resume`.

Добавить сотрудника — одна строка в словаре `AGENTS` в `server.py`.

## Грабли, на которые уже наступили

Если будешь править — не убирай, оно всё выстрадано:

- `stdin=DEVNULL` для `claude`: иначе он ждёт stdin три секунды на каждом запуске.
- `limit=16MB` на пайп: дефолтные 64 КиБ рвут запуск на первой большой строке
  `tool_result`.
- `start_new_session=True`: без своей группы процессов «Стоп» оставляет детей агента
  (`pytest`, `npm`) сиротами.
- Из потока берём только `text_delta`. `thinking_delta` и `signature_delta` — это
  размышления и base64-подпись, им в чате не место.
- Тулы берём из события `assistant`, текст — только из дельт: текстовые блоки в
  `assistant` дублируют дельты, и ответ задваивается.
- Консультацией считается команда, где харнесс **запускается** и ему **передают
  вопрос** — оба признака обязательны. Одного упоминания имени мало: `grep` по имени
  проекта в памяти соседки — это чтение (оно разрешено), а не обращение к ней, и в
  ленте показывался фантомный блок консультации. Отсюда `\s` после имени харнесса в
  регулярке: `deepagents-something` — не вызов `deepagents`.
- Цель консультации — каталог, **в который заходят** (`cd …/crew_steve`), а не любое
  упоминание пути. Спрашивающий обычно пишет свой путь в текст вопроса («Лора
  спрашивает, из `/…/crew_lora`»), и по простому совпадению подстроки выходило, что
  агент консультируется сам с собой. Себя из кандидатов исключаем всегда.
- Консультация дольше 10 минут упирается в потолок Bash, агент перезапускает её в фоне
  и получает расписку «Command running in background». Выдавать её за ответ нельзя:
  из расписки берём путь к файлу вывода и ждём, когда агент его прочитает.
- **Рост файла не говорит, жив ли сосед.** `claude -p` пишет не постепенно, а один раз
  в конце: файл стоит на нуле всё время работы и разом становится полным. Поэтому
  пустой файл — это «ещё думает», а не «завис». Чтобы видеть жизнь по-настоящему,
  вложенный вызов должен идти с `--output-format stream-json`.
- Ждать ответа голым `sleep` харнесс запрещает — нужен until-цикл
  (`until [ -s <файл> ]; do sleep 10; done`). Без явного указания агент читает файл
  один раз, видит пустоту и заканчивает.
- **Проверяя правку, убедись, что сервер перезапустился.** `uvicorn` не занимает
  занятый порт, а пишет «address already in use» в лог и продолжает жить старым
  процессом. Несколько «проверок» ушли в старый код, пока это не вскрылось.
- В преамбуле про `timeout` важно уточнять, что речь о **параметре инструмента Bash**:
  без этого агент оборачивает команду в утилиту `timeout`, которой на macOS нет, и
  консультация падает на `command not found`.
- Вопрос к соседу доезжает тремя разными путями, и читать надо все три: аргументом
  флага (`claude -p "..."`), через конвейер (`printf … | …`) и heredoc. Если не
  распознали ни один, показываем саму команду.
